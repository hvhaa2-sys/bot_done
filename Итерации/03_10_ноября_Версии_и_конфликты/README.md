# 3. Контролируемое обновление базы

Встреча: 10 ноября 2026 года, предварительно. Ведут: У3 и У5.

## Результат показа

Плохое изменение остаётся в черновике, хороший выпуск можно воспроизвести и откатить.

## Что уже есть на 22.10.2026

Версии, быстрый экзамен, конфликты и откат уже реализованы. Автоматическая проверка не разрешает за человека любое смысловое противоречие.

## Сценарий на 5–8 минут

1. Зафиксировать текущую версию базы и ответ по ней.
2. Внести подтверждённый факт, проверить черновик и опубликовать.
3. Добавить противоречащий источник и показать блокировку публикации.
4. Вернуть предыдущую версию и проверить, по какой базе отвечает бот.

## Приёмка

- [ ] Черновик до публикации не меняет ответы работающего помощника.
- [ ] Обнаруженное противоречие не публикуется без разбора.
- [ ] В журнале диалога есть номер использованной версии.
- [ ] После отката возвращаются прежние знания, несохранённый черновик не теряется.
- [ ] Есть собственные сценарии команды для ошибок публикации и отката.

## Ответственность участников

- У1: согласовать правила публикации и последствия отката с владельцем базы.
- У2: составить 10 реальных расхождений с датами и источниками.
- У3: проверить сбои публикации, регрессию и откат, зафиксировать результаты.
- У4: подготовить регрессионные вопросы к изменяемым фактам.
- У5: повторить весь путь через админку без подсказок разработчика и записать демо.
