# 4. Воспроизводимое сравнение поиска

Встреча: 18 ноября 2026 года, предварительно. Ведут: У4 и У2.

## Результат показа

BM25, эмбеддинги GigaChat и RRF сравниваются на одинаковых источниках и разметке.

## Что уже есть на 22.10.2026

Стенд трёх методов готов. Предварительный BM25: Recall@8 0,8875, MRR 0,654 на 40 вопросах из 480 строк. Разметка не независимая. На 21.10 embedding API вернул HTTP 402, полное сравнение не выполнено.

## Сценарий на 5–8 минут

1. Объяснить разницу между поиском слов, близостью векторов и объединением рангов.
2. Показать соответствия вопрос–источник и правила независимой проверки.
3. Запустить один и тот же корпус и запросы для трёх методов.
4. Разобрать ошибки, Recall@8, MRR и цену эксперимента, выбрать дальнейший вариант.

## Приёмка

- [ ] Новые вопросы размечены и проверены менеджером до настройки на них.
- [ ] Все методы используют одинаковые фильтры и одинаковую выборку.
- [ ] Выдачи и параметры сохранены, другой участник повторяет результат.
- [ ] Если доступа к embeddings нет, в отчёте остаётся только BM25; сравнение не считается завершённым.
- [ ] Качество поиска не выдают за процент правильных ответов ассистента.

## Ответственность участников

- У1: согласовать исследовательский вопрос и критерий выбора метода.
- У2: разметить источники для новых вопросов, получить независимую проверку менеджера.
- У3: обеспечить одинаковые фильтры и обособить эксперимент от рабочего бота.
- У4: завершить три прогона, проверить Recall/MRR, задержку и разбор ошибок.
- У5: повторить опыт по инструкции и проверить сохранность всех выходных файлов.
