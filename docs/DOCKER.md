# Docker: запуск, обновление и восстановление

Один экземпляр обслуживает один бизнес. В контейнере приложение работает от UID 10001.
Всё изменяемое состояние находится в именованном томе `assistant-data`, примонтированном в
`/app/data`: SQLite, KB, версии базы и ежедневные копии. Контейнер слушает 8000, на хосте
порт опубликован только на `127.0.0.1`. Снаружи используйте SSH-туннель или свой HTTPS-прокси.

## Чистая установка

Нужны Docker Engine и Docker Compose 2.30+ (поддержка `env_file.format: raw`). Docker Desktop
на macOS включает оба. На Linux установите Docker по официальной инструкции. Python на хосте
не обязателен: при отсутствии Python 3.11+ мастер использует официальный образ Python.

После скачивания проекта:

```bash
./setup
docker compose up -d --build --wait
```

Мастер спросит ключ GigaChat, необязательный токен Telegram и токен админки. Если последний
оставить пустым, создаст случайный. Секреты не печатаются, `.env` получает права 600.
Существующий `.env` мастер не перезаписывает. Ключи получаются отдельно у провайдеров.
Для входа используйте ADMIN_TOKEN из своего `.env` на странице `http://localhost:8000`.

Для первого знакомства без модели, Telegram и внешних запросов:

```bash
./setup --demo --non-interactive
docker compose up -d --build --wait
```

В demo бот использует mock. Приложение автоматически создаёт SQLite. База из дистрибутива
копируется в новый том один раз. Уже существующую, в том числе намеренно пустую KB, образ
не заменяет. В этом дистрибутиве лежат материалы пилотного клиента: другой бизнес должен
заменить их собственными перед подключением клиентских чатов.

Если 8000 занят, задайте порт на хосте:

```bash
ASSISTANT_PORT=8001 docker compose up -d --build --wait
```

При работе с другим env-файлом задавайте **обе** настройки: `--env-file` управляет интерполяцией
Compose, `ASSISTANT_ENV_FILE` выбирает файл, передаваемый внутрь приложения:

```bash
./setup --demo --non-interactive --env-file .env.demo
ASSISTANT_ENV_FILE=.env.demo docker compose --env-file .env.demo up -d --build --wait
```

Контейнер всегда использует `/app/data`, внутренний порт 8000 и `ADMIN_HOST=0.0.0.0`.
Значения DB_PATH, KB_DIR, ADMIN_PORT и ADMIN_HOST из `.env` намеренно перекрыты настройками
Compose. Публикация порта на хосте остаётся локальной.

## Сертификаты MAX и GigaChat

Публичный корневой сертификат Минцифры входит в образ по пути
`/app/app/certs/russian_trusted_root_ca.pem` (происхождение — `app/certs/README.md`).
Клиент официального MAX API использует его автоматически. Для GigaChat проверка TLS по
умолчанию выключена, как и раньше (`GIGACHAT_VERIFY_SSL=false`). Если включить её, встроенный
сертификат подхватится сам: задайте `GIGACHAT_VERIFY_SSL=true`, а `GIGACHAT_CA_BUNDLE` можно
оставить пустым. Явный `GIGACHAT_CA_BUNDLE` нужен, только если сертификат лежит по другому пути
или их несколько:

```bash
GIGACHAT_VERIFY_SSL=true
GIGACHAT_CA_BUNDLE=/app/app/certs/russian_trusted_root_ca.pem
```

`GIGACHAT_CA_BUNDLE` перекрывает `GIGACHAT_VERIFY_SSL`. Включение проверки обратимо: верните
`GIGACHAT_VERIFY_SSL=false` и перезапустите контейнер.

## Обновление

Замените код дистрибутива, сохранив `.env` и именованный том:

```bash
./setup backup ../before-update.tar.gz
docker compose up -d --build --wait
```

Образ устанавливает зависимости из `requirements.lock` с проверкой хешей. Базовый образ
Python 3.13-slim закреплён проверенным digest (21.10.2026). Для его осознанного обновления передайте
`docker compose build --build-arg PYTHON_IMAGE=python@sha256:<проверенный-digest>`.
Не используйте `docker compose down -v` для обновления: `-v` удаляет постоянный том.

## Полная копия

```bash
./setup backup ../assistant-2026-10-21.tar.gz
```

Команда останавливает только контейнер этого Compose-проекта. Если он работал до операции,
после неё запускается снова, в том числе при ошибке резервирования. Входящие сообщения
не обрабатываются на время копирования. Другой процесс не должен писать в этот же том.

В архиве: всё содержимое data/, манифест путей и SHA-256. SQLite копируется через backup API,
включая подтверждённые транзакции WAL. SQLite-файлы проверяются через integrity_check.
Архив не включает расположенный вне data/ `.env`, поэтому сохраните его отдельно в своём
хранилище секретов. Сам архив содержит деловые переписки и тоже требует защищённого хранения.

Копия сохраняется вне data/, с правами 600. Архив нельзя случайно перезаписать, лимит
распакованного снимка — 512 МБ. Символические ссылки в data/ не поддерживаются.

Ежедневные копии `app/backup.py` сохраняют только SQLite. Для миграции и полного восстановления
с версиями KB используйте именно `./setup backup`.

## Восстановление

```bash
./setup restore ../assistant-2026-10-21.tar.gz --yes
docker compose up -d --wait
```

`--yes` подтверждает замену data/. Перед восстановлением команда создаёт рядом отдельный архив
предыдущего состояния. Проверяет пути, SHA-256 и SQLite до замены рабочих файлов. Не допускает
символические ссылки, выход из каталога и подмену манифеста. Если замена прервана обычной ошибкой,
возвращает прежние файлы. При аварийном выключении питания используйте предохранительный архив.

Код приложения тоже должен соответствовать снимку: откат данных не откатывает Docker-образ
и миграции схемы. Для переноса на другой компьютер нужны тот же релиз, архив и отдельно `.env`.

## Проверки

```bash
./setup check
./setup smoke
```

`check` проверяет Compose и подключения через штатный `app.check`. На реальном провайдере он
обращается к внешним API. Не печатайте `docker compose config` без `--quiet`: там могут быть ключи.

`smoke` использует отдельное имя Compose-проекта, отдельный том, случайный порт и mock.
Проверяет сборку, /health, сохранность после пересоздания контейнера, копирование всего состояния,
замену данных, восстановление SQLite и файлов, повторный запуск. Временный том удаляется после
проверки. Существующий запуск проекта и его `.env` smoke-тест не использует.

Если Docker Engine недоступен, локальные тесты архива и мастера всё равно можно выполнить:

```bash
.venv/bin/python -m pytest tests/test_deploy.py -q
```

Это не заменяет настоящий `./setup smoke`. Результат контейнерной проверки записывается в
`docs/КООРДИНАЦИЯ.md` отдельно от локальных тестов.
