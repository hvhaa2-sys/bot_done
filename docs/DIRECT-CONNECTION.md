# MAX и GigaChat при включённом Happ

На Mac приложение может указать IPv4 физического интерфейса как исходящий адрес
соединений к MAX и GigaChat. На проверенной конфигурации Happ это даёт доступ к
обоим API при включённом VPN. Правила Happ, маршруты macOS и системное хранилище
сертификатов приложение не меняет. С другими VPN и режимами блокировки результат
может отличаться.

## Включение

В локальном `.env`:

```dotenv
DIRECT_INTERFACE=auto
```

`auto` выбирает первый интерфейс en0…en9 с IPv4; можно указать конкретный, например
`en0`. Пустое значение отключает привязку. Настройка действует только на macOS;
в Linux и Docker используется обычное подключение. После изменения нужен
перезапуск уже работающего экземпляра бота.

Привязка применяется к клиентам MAX и GigaChat (включая OAuth). Telegram и другие
провайдеры её не используют. Запросы к localhost и loopback-адресам, в том числе
песочнице MAX, идут обычным способом.

## Смена сети

Адрес проверяется при первом запросе и затем перед запросами не чаще раза в
30 секунд. Проверка интерфейса выполняется вне цикла обработки сообщений.
При смене IPv4 новые запросы получают новый пул соединений, старые ответы могут
дочитаться. Дополнительных повторов отправки сообщений транспорт не делает.

Если адреса нет, используется системный маршрут: при включённом VPN сервис может
оказаться недоступен. После появления интерфейса транспорт обнаружит его при
следующей проверке. Успех запроса во время переключения Wi-Fi не гарантируется;
повторы выполняются существующей логикой клиентов MAX и GigaChat.

## Сертификат MAX

Официальный API MAX использует российскую цепочку доверия. Клиент для
`platform-api2.max.ru` и `platform-api.max.ru` дополнительно загружает публичный
Russian Trusted Root CA из `app/certs/russian_trusted_root_ca.pem`. Сертификат
включён в Docker-образ. Происхождение, срок действия и отпечаток — в
`app/certs/README.md`.

Проверка цепочки и имени сервера остаётся включённой. Дополнительный CA действует
только в SSL-контексте официального клиента MAX, не меняет certifi или macOS и
не применяется к произвольному `MAX_API_URL`. Настройка проверки TLS GigaChat
осталась прежней (`GIGACHAT_VERIFY_SSL`); эта правка её не усиливает и не отключает.

## Проверка

`python -m app.check` проверяет модель и подключения, но не запускает опрос событий.
Он также выполняет тестовый вопрос через модель. Для узкой сетевой диагностики
достаточно MAX `GET /me`, `GET /subscriptions` и GigaChat OAuth + `GET /models`.
Не запускайте второй `python -m app` рядом с рабочим ботом: два опроса конкурируют
за события клиентов.

Автотесты `tests/test_netbind.py` проверяют исчезновение и возврат интерфейса,
смену адреса с незакрытым ответом, параллельные запросы, локальные адреса и ошибки.
`tests/test_tls.py` проверяет доверенный CA, проверку имени и область действия.
В этих тестах нет запросов к настоящим ботам. Отключение Wi-Fi на рабочем Mac
специально не производится: смена сети проверяется подменой адресов.

- Docker-образ собран; внутри без сети проверены доверенный CA, отсутствие рабочих
  ключей и отсутствие привязки интерфейса на Linux. Тестовая Colima остановлена.
- Единственный рабочий LaunchAgent перезапущен: `/health` вернул 200,
  в журнале есть запуск MAX `se14957548_bot`. Режимы существующих подключений
  `off` и `observe` не изменены.

  следующий шаг — `/manager` у бота и разрешение подключения в админке.
