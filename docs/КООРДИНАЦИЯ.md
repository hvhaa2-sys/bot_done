## Решения, о которых договорились

- Кандидат до утверждения не попадает в поиск: живёт в таблице `candidates`, не в `data/kb`.
- Утверждённый кандидат пишется в `data/kb/notes/Из переписки/<ТЦ>.md` (или `Общее.md`).
- Суммы из переписки не становятся ценами: если в ответе сумма не из `prices.csv`, утверждение блокируется
  с подсказкой добавить позицию в прайс (как в «Обучении»). Решение «цены только из prices.csv» не меняем.
- Статусы кандидата: `new`, `approved`, `rejected`; `superseded` добавим вместе с версиями базы (Неделя 2).
- `eval/run_eval.py` и наборы `eval/questions*.csv` — общие: Claude Code только читает их для экзамена
  перед публикацией, правки в `eval/` делает Codex (Неделя 3). Нужна правка — пишем в «Вопросы».
- Для Docker (Неделя 4): всё изменяемое состояние живёт в `data/` (база `data/kb`, версии `data/kb_versions`,
  `data/app.db`, `data/backups`) — это один постоянный том.
- Наблюдение (22.10): `observe` сохраняет сообщения в отдельную `observed_messages`, не вызывает генерацию
  ответа, не отправляет черновики и сводки. Разбор содержательных ответов менеджера использует прежний
  механизм кандидатов; до ручного утверждения они не входят в RAG. На текущем аккаунте пользователя
  включено `observe` и для подключения, и по умолчанию для новых. Не включать ему `auto` без просьбы.
  Инструкция и ограничения — `docs/OBSERVE.md`. Изменения пока локальные, в GitHub не отправлялись.
- Codex закончил и освободил файлы: `Dockerfile`, `docker-compose.yml`, `.dockerignore`, `setup`,
  `deploy/container/`, `tools/deploy.py`, `tests/test_deploy.py`, `docs/DOCKER.md`,
  `eval/retrieval_eval.py`, `eval/retrieval_qrels.csv`, `tests/test_retrieval_eval.py`, `docs/RETRIEVAL.md`.
  Результаты поиска — `eval/retrieval_results/`: BM25 на начальной разметке 40/480 вопросов,
  Recall@8 = 0,8875, MRR ≈ 0,654. Разметка требует независимой проверки менеджером.

- Версии базы (Неделя 2, Claude Code, 21.10): бот отвечает по снимку `data/kb_versions/<номер>`, `data/kb` —
  черновик менеджера. Снимки лежат рядом с `DB_PATH` (в Docker — `/app/data/kb_versions`, тот же том).
  Перед публикацией — быстрый экзамен без модели по `EXAM_FILES` (по умолчанию `eval/questions*.csv`,
  пусто — только проверка разделов по заголовкам и разметка из журнала). В `.env.example` можно добавить
  `EXAM_FILES=` с комментарием — это для Codex, файл его. Режим публикации — в админке (`kb_publish`: auto/manual).
  Первый запуск на пустом томе сам публикует черновик как версию 1.
