## Управление

Подключение с Mac:

```sh
ssh -4 -F /dev/null -i ~/.ssh/buff_bots_ed25519 -o IdentitiesOnly=yes root@193.34.214.187
```

На VPS:

```sh
cd /opt/buff-bots
docker compose ps
curl --fail http://127.0.0.1:8000/health
curl --fail http://127.0.0.1:8040/health
# Перезапуск по отдельности:
docker compose restart sales
docker compose up -d --no-build --wait sales
docker compose restart restaurant
docker compose up -d --no-build --wait restaurant
```

Compose: `/opt/buff-bots/compose.yml`; код — `<сервис>/code`, секреты — `<сервис>/server.env` (600).
Образы: `buff-sales:2026-11-15`, `buff-restaurant:2026-11-15`. Контейнеры используют UID 10001,
read_only, отдельный tmpfs и том данных; журналы ограничены 3 × 10 МБ. Docker включён при загрузке,
контейнеры — restart unless-stopped. GigaChat TLS проверяется с публичным российским корневым сертификатом
в отдельном bundle внутри образа. Рабочие .env на Mac не менялись.
Не публиковать `docker compose config` и логи без проверки: там могут оказаться секреты.

## Копии и откат

Ежедневно около 03:15 Екатеринбурга `buff-bots-backup.timer` запускает `/opt/buff-bots/backup.py`:
согласованный снимок SQLite через backup API, полная KB/версии/остальные данные, SHA256 и проверка восстановления.
Архивы — `/opt/buff-bots/backups/<сервис>/`, остаются последние 7 успешных копий каждого сервиса.

```sh
systemctl list-timers buff-bots-backup.timer
systemctl start buff-bots-backup.service
journalctl -u buff-bots-backup.service --no-pager -n 15
```

На Mac сохранены финальные снимки перед переключением и первые копии с VPS:
`~/buff-bots-migration-2026-11-15/{sales,restaurant}/`.
Эта папка содержит также приватные server.env: не публиковать и не добавлять в git.
С 16.11 включён Mac LaunchAgent local.buff-bots-backup: раз в час загружает последние архивы в
~/Library/Application Support/BuffBotBackups, проверяет SHA256/SQLite и оставляет последние 7.
Журналы pull.log/errors.log находятся там же. При выключенном Mac выгрузка ждёт его включения;
для независимой выгрузки 24/7 нужен постоянно доступный получатель.

Продажник на Mac остановлен через bootout, LaunchAgent `local.ai-sales-assistant` disabled;
его plist сохранён. Ресторанный процесс 36185 остановлен. Старые локальные папки данных не удалялись.
Для возврата на Mac сначала остановить соответствующий контейнер VPS, снять свежую копию его данных
и восстановить её в правильную локальную папку: sales `data/`, restaurant `data/restaurant/`.
Не запускать Mac с устаревшей базой: после переключения новые сообщения уже сохраняются на VPS.
Только после восстановления данных включать sales LaunchAgent или `deploy/restaurant-telegram.sh`.
