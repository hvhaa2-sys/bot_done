# ИИ-помощник менеджера по продажам

Сервис отвечает на типовые вопросы клиентов в Telegram от имени менеджера. Ответы строятся
по базе знаний компании (FAQ и прайс). Пилотный клиент — продажа рекламы в торговом центре.

Три режима:
- **Наблюдение** — бот ничего не пишет клиентам и не присылает карточек, модель не вызывает. Он записывает
  обращения клиентов, ответы менеджера и через сколько она ответила. Это замер «как было до бота» на живых
  чатах, а её ответы становятся предложениями в базу знаний. Удобно начинать пилот с одной-двух недель
  наблюдения: `/mode watch`. В MAX наблюдения нет — там клиентам, кроме бота, никто не ответит.
- **Черновики** — бот присылает менеджеру готовый ответ. Менеджер жмёт «Отправить», «Пропустить»
  или отвечает на карточку своим текстом, и тогда клиенту уходит его вариант.
- **Автоответ** — бот отвечает клиенту сам. Сложные вопросы передаёт менеджеру, а клиенту пишет
  «Уточню и вернусь».

Если менеджер сам пишет клиенту, бот замолкает в этом чате на 30 минут.

Бот помнит выбранные клиентом ТЦ, формат, место, срок и бюджет: до 60 сообщений за последние
3 часа, отдельно для каждого чата. При смене ТЦ сбрасывает прежнее место и тариф арендатора.
Если для цены не хватает параметров, задаёт до двух уточнений, затем передаёт вопрос менеджеру.
Общие условия, подбор по бюджету и однозначные позиции отвечает без лишних уточнений.
Занятость мест подтверждает менеджер.

Тестовый чат в админке тоже сохраняет выбор между вопросами. Кнопка «Новый разговор» сбрасывает
его только в этом браузере; предыдущие проверки остаются в журнале.

## Как устроено

```
Клиент → Telegram Business → адаптер канала → ядро ассистента → решение
                                                  │
           ┌──────────────────────────────────────┤
           │ 1. Стоп-темы (скидки, договор, оплата) → сразу менеджеру
           │ 2. Память выбора и уточнение недостающих параметров
           │ 3. Поиск BM25 по FAQ и прайсу → нет совпадений → менеджеру
           │ 4. Языковая модель отвечает строго по найденному, в JSON с уверенностью
           │ 5. Защита цен: сумма не из найденных строк прайса → менеджеру
           │ 6. Уверенность ниже порога → менеджеру
           └──────────────────────────────────────┘
```

| Папка | Что внутри |
| --- | --- |
| `app/core/` | Ядро: поиск (`knowledge.py`), память выбора (`conversation.py`), защита цен (`price_guard.py`), конвейер ответа (`assistant.py`) |
| `app/llm/` | Модели за общим интерфейсом: GigaChat, любой OpenAI-совместимый API (YandexGPT), `mock` без сети |
| `app/channels/` | `flow.py` — логика режимов, не зависящая от мессенджера; `telegram_business.py` — адаптер Telegram; `max_bot.py` и `max_api.py` — адаптер MAX |
| `app/admin.py` | Веб-админка: обзор и тестовый чат, журнал с отметкой ошибок, база знаний, экзамен, настройки |
| `app/db.py` | SQLite: подключения, журнал диалогов, паузы |
| `eval/` | Стенд оценки качества: тестовые вопросы и метрики |
| `data/kb/` | Рабочая база знаний; тестовый пример — в `tests/fixtures/` |
| `tools/` | Импорт переписки из Telegram Desktop в черновик базы знаний и тестовый набор |
| `tests/` | 563 автотестов, работают без сети |

## Быстрый старт

Нужны Python 3.11+ и uv. На Mac для разработки используется Python 3.13.

```bash
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python --require-hashes -r requirements.lock
cp .env.example .env        # по умолчанию LLM_PROVIDER=mock, работает без ключей
.venv/bin/python -m app
```

Откройте `http://localhost:8000/?token=change-me` и задайте вопрос в песочнице.

## Проверки разработчика

```bash
make install-dev   # инструменты разработки и импорта документов в .venv
make check         # Ruff, тесты и покрытие строк/веток
make audit         # известные уязвимости зависимостей
make lock          # пересобрать lock-файлы после изменения requirements*.txt
```

`requirements.lock` фиксирует зависимости приложения, `requirements-dev.lock` — полное окружение
разработки. Оба содержат точные версии и хеши пакетов; они собраны для Python 3.11+ на разных платформах.
Списки прямых зависимостей остаются в `requirements.txt`, `requirements-tools.txt` и `requirements-dev.txt`.
Команды запускают модули через `.venv/bin/python`, поэтому не зависят от путей в скриптах старого окружения.

## Админка

- **Обзор** — метрики, тестовый чат (видно, на какие строки базы опирался бот) и карточка состояния: модель, Telegram, база, последний экзамен.
- **Обучение** — вопросы, на которые у бота не нашлось ответа, собраны в группы похожих. Менеджер пишет ответ один раз — он попадает в базу знаний, и бот сразу проверяет, что теперь отвечает сам.
- **Диалоги** — журнал с фильтрами и поиском. Кнопка «Ошибка» открывает разбор: неверные факты или неверное решение.
  Менеджер выбирает правильное действие, а для ответа указывает исправленный текст и проверяемые факты.
  В CSV для экзамена попадают только подтверждённые примеры. Например, неправильная цена остаётся вопросом,
  на который бот должен ответить, с проверкой правильной суммы. Исходный ответ сохраняется в журнале.
- **База знаний** — прайс с поиском: цену можно поправить прямо на странице, добавить или удалить позицию, а весь прайс — скачать, поправить в Excel и загрузить; частые вопросы и стоп-темы правятся прямо на странице.
- **Экзамен** — прогон `eval/questions.csv` одной кнопкой на текущей модели.
- **Импорт переписки** (на странице базы знаний) — загрузите выгрузку Telegram, и админка покажет, сколько клиенты ждали ответа до бота, долю повторяющихся вопросов и черновик FAQ; на «Обзоре» появится блок «Было → стало».
- **Настройки** — модель, режим, обращение на «вы» или «ты», подпись менеджера, тексты бота, паузы, склейка сообщений, вечерняя сводка в Telegram, расписание автоответа (днём черновики, вечером и в выходные — сам). Применяются сразу, без перезапуска; ключи и токены остаются в `.env`.

## Проверка в Telegram за 10 минут

Нужны два аккаунта Telegram: ваш (в роли менеджера) и любой второй (в роли клиента, например друга).

1. В @BotFather: `/newbot` → имя → username на `bot`. Скопируйте токен в `.env`: `TELEGRAM_BOT_TOKEN=...`.
2. Там же: `/mybots` → ваш бот → Bot Settings → Secretary Mode (раньше Business Mode) → включить.
3. Проверка: `.venv/bin/python -m app.check` — все пункты должны быть с ✓.
4. Запуск: `.venv/bin/python -m app`. Ноутбук не закрывать, пока проверяете.
5. Откройте своего бота в Telegram и нажмите «Старт».
6. Telegram → Настройки → Автоматизация чатов → добавить бота → разрешить отвечать.
   **Для проверки выберите только чат с тестовым аккаунтом**, иначе бот начнёт отвечать всем.
   Сами в этот чат не пишите: когда менеджер пишет клиенту, бот уступает и молчит там 30 минут
   (снять паузу — `/resume` в чате с ботом или кнопка в админке).
7. Со второго аккаунта напишите вам: «Сколько стоит экран на фуд-корте в ВЕЕР Молл?»
   В режиме черновиков карточка придёт в чат с ботом — нажмите «Отправить».
8. В чате с ботом: `/mode auto` — теперь бот отвечает клиенту сам. Попробуйте «Дадите скидку?»
   и голосовое: их бот передаст вам.

Всё, что произошло, видно в админке: `http://localhost:8000/?token=…` (адрес печатается при запуске).

## Подключение к Telegram

1. Создайте бота в @BotFather, затем в Bot Settings включите **Secretary Mode** (раньше Business Mode). Токен впишите в `.env`.
2. Менеджер пишет боту `/start`, чтобы бот мог присылать ему черновики.
3. В Telegram менеджера: Настройки → Автоматизация чатов → добавить бота (до мая 2026 путь был
   «Telegram для бизнеса → Чат-боты»). Premium с Bot API 10.0 не нужен.
   Разрешите отвечать на сообщения. Можно выбрать, в каких чатах бот работает.
4. Команды в чате с ботом: `/mode watch` (наблюдение), `/mode draft`, `/mode auto`, `/status`.

Ограничение Telegram: бот может ответить только в чатах, где клиент писал за последние 24 часа.

## Подключение к MAX

Второй канал на случай, если Telegram в России будет работать плохо. Бот в MAX работает от организации
(ИП, юрлицо или самозанятый после верификации на dev.max.ru), поэтому устроен иначе, чем в Telegram:
клиенты пишут прямо в бот компании, а не в личку менеджеру.

1. На dev.max.ru создайте бота организации и скопируйте токен в `.env`: `MAX_BOT_TOKEN=…`.
2. `python -m app.check` проверит токен и подскажет, если у бота осталась подписка-вебхук (она мешает опросу).
3. Запустите приложение. Менеджер открывает бота в MAX и пишет `/manager` — сюда будут приходить
   карточки и черновики. Первый менеджер подключается сам, следующих разрешают в админке: Обзор → Подключения.
4. Команды менеджера те же: `/mode draft`, `/mode auto`, `/status`, `/resume`. Ответить клиенту — кнопкой
   «Отправить» под черновиком или ответом на карточку своим текстом (написать в чат клиента напрямую в MAX нельзя).

Логика ответов, проверки и вечерняя сводка общие с Telegram. Окна в 24 часа, как в Telegram, нет.
Адрес API и поля сверены с официальным клиентом MAX; с настоящим ботом организации адаптер ещё не запускался.

## Автозапуск на Mac

Для тестов и показа: бот работает в фоне, сам стартует при входе в систему и поднимается после сбоя.
Пока он работает, Mac не засыпает от бездействия, но с закрытой крышкой спит — для пилота нужен сервер.

```bash
deploy/mac-autostart.sh        # включить; после правок кода или .env — запустить ещё раз
deploy/mac-autostart.sh off    # выключить
tail -f ~/Library/Logs/ai-sales-assistant.log   # что делает бот
```

## Запуск на сервере

Для пилота бот должен работать круглосуточно, а база с перепиской — храниться в России.
Хватит VPS с 1 ГБ памяти (RuVDS, FirstVDS и т. п., ~300–350 ₽ в месяц), Ubuntu 22.04+ с Python 3.11+.

```bash
sudo useradd -m bot && sudo mkdir -p /opt/ai-sales-assistant && sudo chown bot /opt/ai-sales-assistant
# скопировать проект в /opt/ai-sales-assistant (scp или git), затем от пользователя bot:
cd /opt/ai-sales-assistant && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # вписать токен бота, ключ GigaChat, свой ADMIN_TOKEN
sudo cp deploy/ai-sales-assistant.service /etc/systemd/system/
sudo systemctl enable --now ai-sales-assistant
journalctl -u ai-sales-assistant -f   # логи
```

- Админка слушает только `127.0.0.1` (`ADMIN_HOST`). Открывать её с ноутбука через SSH-туннель:
  `ssh -L 8000:localhost:8000 bot@сервер`, затем `http://localhost:8000/?token=…`.
- `GET /health` без токена отвечает `{"ok": true}` — для мониторинга.
- Раз в сутки база копируется в `data/backups/`, хранятся 14 последних копий.

## Подключение модели

GigaChat для физлиц бесплатен в пределах freemium (только некоммерческое использование, для работы
с клиентом нужен тариф юрлица или ИП): 250 млн токенов моделей Lite и 40 млн Pro
на 12 месяцев. Для учебного проекта и пилота этого с запасом.

1. Войдите на developers.sber.ru через Сбер ID и откройте личное пространство в Studio.
2. Создайте проект GigaChat API.
3. В настройках API получите ключ авторизации (Authorization key) и пропишите его в `.env`:

```
LLM_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=...
GIGACHAT_SCOPE=GIGACHAT_API_PERS
```

Если появится ошибка SSL, оставьте `GIGACHAT_VERIFY_SSL=false` или установите сертификаты Минцифры.

YandexGPT или другая модель с OpenAI-совместимым API: `LLM_PROVIDER=openai` и переменные `OPENAI_*`.

## База знаний

Всё лежит в `data/kb/` и правится в админке («База знаний»):

- `faq.md` — каждый вопрос начинается с `## `, под ним ответ;
- `prices.csv` — колонки `format,placement,period,price_rub,notes`. Только отсюда бот берёт цены;
- `stop_topics.txt` — слова, при которых бот сразу зовёт менеджера;
- `notes/` — заметки по темам: трафик, требования к макетам, правила ТЦ. Папку можно открыть как хранилище Obsidian.
  Один файл — одна тема, в начале указан ТЦ:

  ```markdown
  ---
  тц: ВЕЕР Молл
  источник: КП ВЕЕР 2026
  ---
  ## Какие требования к ролику для экранов?
  MP4, до 15 секунд, 1920×1080, без звука.
  ```

  Каждый раздел `## ` бот находит отдельно, а когда клиент называет ТЦ, заметки других ТЦ не учитывает.
  Цены пишите в `prices.csv`, а не в заметки: сумму, которой нет в прайсе, бот клиенту не назовёт.
  Вопросы, по которым документы расходятся, собраны в `docs/вопросы_по_базе.md`.

## База, которая растёт из переписки

Готовая база не обязательна. Когда менеджер отвечает клиенту — на карточку бота или прямо в чате, —
бот выделяет из ответа общие факты («сколько стоит…», «какие требования к ролику…») и предлагает
их в базу. Личное (бронь, скидки, обещания) не берётся, телефоны и почты скрываются.

Предложения видны в админке («Обучение» → «Из переписки») и приходят в вечерней сводке с кнопками ✓/✗.
До утверждения бот их не использует. Утверждённое попадает в заметки `data/kb/notes/Из переписки/`.
Если в ответе сумма, которой нет в прайсе, утвердить нельзя: сначала добавьте позицию в прайс.
На «Обзоре» таблица «Как растёт база» показывает по неделям, сколько вопросов бот закрыл сам.

## Версии базы: проверка перед публикацией и откат

Всё, что меняется в базе — прайс, FAQ, заметки, утверждённые факты, — сначала попадает в черновик. Бот отвечает
по опубликованной версии. Перед публикацией черновик за полсекунды проходит проверку без нейросети:

- поиск по-прежнему находит ответы на контрольные вопросы (`eval/questions*.csv` и разобранные ошибки из журнала);
- каждый вопрос из FAQ и заметок находится по своей формулировке;
- нет новых противоречий: двух цен на одно место, старой цены в заметке после смены прайса, разных цифр
  в ответах на один и тот же вопрос.

Если всё в порядке, версия публикуется сразу (или по кнопке — «Настройки» → «Изменения базы знаний»). Если нет,
бот продолжает отвечать по прошлой версии, а на странице «База знаний» видно, что не так, со ссылками на заметки.
Любую прошлую версию можно вернуть кнопкой «Вернуть», в журнале диалогов видно, по какой версии ответил бот.

Демо для защиты — новый бизнес с одним прайсом, база растёт из ответов менеджера:

```bash
python -m tools.demo_cold_start            # на модели из .env
python -m tools.demo_cold_start --offline  # без сети
python -m tools.demo_cold_start --offline --admin 8010   # и открыть админку демо
```

## Документы компании → база знаний

КП, прайсы, презентации и регламенты можно разобрать в текст и перенести факты в базу:

```bash
pip install -r requirements-tools.txt
python -m tools.import_docs ~/Downloads/Документы
```

Тексты появятся в `data/import/docs/`, список — в `index.csv`. Файлы с паролями и доступами инструмент помечает
«НЕ ПЕРЕНОСИТЬ В БАЗУ», с телефонами, почтами и реквизитами — «проверить перед переносом». Цены из текстов переносите
в `prices.csv`, остальное — заметками в `notes/`.

## Импорт реальной переписки

Самый быстрый способ собрать базу знаний и тестовый набор — выгрузить переписку менеджера.

1. Telegram Desktop → Настройки → Продвинутые настройки → Экспорт данных Telegram.
   Отметить «Личные чаты», формат «Машиночитаемый JSON», медиа не нужны.
   Можно выгрузить и отдельный чат: ⋮ → Экспорт истории чата → JSON.
2. Запустить:

```bash
python -m tools.import_telegram result.json
# для отдельных чатов: python -m tools.import_telegram chat1.json chat2.json --me "Анна"
```

В `data/import/` появятся:
- `pairs.csv` — пары «вопрос клиента — ответ менеджера», телефоны, почты и номера карт скрыты;
- `faq_draft.md` — частые вопросы, сгруппированные по смыслу, с её последним ответом;
- `questions_real.csv` — тестовый набор; суммы из её ответов уже проставлены как ожидаемые факты.

Скрипт также считает, какую долю обращений составляют повторяющиеся вопросы.
Это главная цифра для защиты: сколько работы можно отдать боту.

Дальше черновик нужно проверить глазами: цены перенести в `prices.csv`, устаревшее убрать,
затем положить файл в `data/kb/faq.md`. В `questions_real.csv` вопросы, на которые бот
отвечать не должен (скидки, договор), пометьте `escalate`.

```bash
python -m eval.run_eval --questions data/import/questions_real.csv --compare mock,gigachat
```

## Оценка качества

```bash
python -m eval.run_eval --provider mock
python -m eval.run_eval --compare mock,gigachat   # сравнение моделей
python -m eval.run_eval --questions eval/questions_live.csv   # живые сообщения: опечатки, сленг
```

Метрики:
- `decision_accuracy` — бот правильно решил, отвечать или звать менеджера;
- `unsafe_answers` — ответил сам там, где нельзя (самая опасная ошибка);
- `missed` — позвал менеджера, хотя ответ есть в базе;
- `content_hit` — в ответе есть нужные факты;
- `price_guard_trips` — сколько выдуманных сумм поймала защита;
- время ответа (среднее и p95).

Результаты по каждому вопросу сохраняются в `eval/results_<модель>.csv`.

Базовая линия `mock` (без модели, просто первый найденный фрагмент): точность решений 94%,
2 опасных ответа на вопросы, которых нет в базе. Задача настоящей модели — убрать именно их.

## Защита от лишних трат

- Подключить бота может любой, кто знает его имя, но отвечать он будет только после «Разрешить»
  в админке (Обзор → Подключения). Первый менеджер одобряется сам. Пока подключение не одобрено,
  модель на него не тратится.
- Дневной лимит обращений к модели (по умолчанию 1000). После него вопросы уходят менеджеру без модели.
- Лимит сообщений в час из одного чата (по умолчанию 30): спамер получает паузу на час, менеджер — одно предупреждение.
- Длинные сообщения обрезаются до 1500 символов; попытки вытащить инструкции бота клиенту не уходят.
- На «Обзоре» видно, сколько обращений и токенов потрачено сегодня и примерно во сколько это обошлось.
- Вход в админку: после 5 неверных токенов за 10 минут вход с этого адреса закрыт на 10 минут.

Лимиты меняются в «Настройки → Защита от лишних трат».
