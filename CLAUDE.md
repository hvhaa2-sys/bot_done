# ИИ-помощник менеджера по продажам

Учебный проект (УрФУ, ИРИТ-РтФ, ИВТ, 2 курс, проектный практикум, команда 5 человек).
Сервис отвечает на типовые вопросы клиентов в мессенджере от имени менеджера по базе знаний компании.
Пилотный клиент — менеджер, продающая рекламу в торговом центре в Екатеринбурге; клиенты пишут ей в Telegram.
Защита перед комиссией, где в основном бизнесмены: нужны живое демо, метрики пилота и экономика.

**В проекте работают два агента (Claude Code и Codex). Перед правками прочитай `docs/КООРДИНАЦИЯ.md`: кто что делает и какие файлы заняты.**

## Архитектура

Конвейер ответа (`app/core/assistant.py`):
1. Стоп-темы (`data/kb/stop_topics.txt`: скидки, договор, оплата…) → сразу менеджеру, модель не вызывается.
2. Поиск BM25 по FAQ и прайсу (`app/core/knowledge.py`, стемминг Snowball в `text.py`). Ниже `RETRIEVAL_MIN_SCORE` → менеджеру.
3. Модель отвечает строго по найденным фрагментам и возвращает JSON `{answer, confidence, needs_manager}`.
4. Защита цен (`price_guard.py`): любая сумма в ответе, которой нет в `prices.csv`, → менеджеру.
5. Уверенность ниже `CONFIDENCE_THRESHOLD` → менеджеру.

- `app/llm/` — модели за интерфейсом `LLMProvider`: `gigachat` (REST, OAuth), `openai` (любой OpenAI-совместимый API, в т.ч. YandexGPT), `mock` (без сети, отдаёт первый фрагмент контекста).
- `app/channels/flow.py` — логика режимов, не зависит от мессенджера. Новый канал (MAX) = новый адаптер рядом с `telegram_business.py`, ядро не трогаем.
- `app/channels/telegram_business.py` — aiogram 3, Telegram Business: `business_connection`, `business_message`, ответ клиенту через `business_connection_id`. Хендлеры регистрируются в `make_router()` (фабрика — чтобы тесты могли создавать несколько диспетчеров).
- Режимы: `draft` — карточка менеджеру с кнопками «Отправить/Пропустить», ответ на карточку своим текстом = правка; `auto` — бот отвечает сам, при эскалации клиенту уходит «Уточню и вернусь». Если менеджер пишет в чат сам, бот молчит `MANAGER_PAUSE_MINUTES`.
- `app/admin.py` — FastAPI-админка без шаблонизатора (HTML в f-строках, всё через `html.escape`), пять разделов: «Обзор» (метрики, тестовый чат с источниками ответа, карточка состояния, режимы подключений), «Диалоги» (фильтры, поиск, кнопка «Ошибка» → CSV в формате экзамена), «База знаний» (прайс с поиском, скачать/загрузить CSV; FAQ и стоп-темы правятся прямо в браузере), «Экзамен» (прогон `eval/questions.csv` кнопкой на текущей модели, итог хранится в таблице `settings` под ключом `exam_last`), «Настройки».
- `app/services.py` — настройки из админки хранятся в SQLite (таблица `settings`) поверх `.env` и применяются без перезапуска: модель (Lite/Pro/Max/заглушка), режим для новых подключений, тексты «Уточню и вернусь» и приветствия, паузы, пороги, расписание автоответа. `auto_allowed()` — в рабочее время (по умолчанию выкл., часовой пояс `TIMEZONE`, по умолчанию Asia/Yekaterinburg) подключения в `auto` работают как `draft`. Ключи и токены — только в `.env`.
- Поиск понимает «живые» сообщения: `KnowledgeBase.normalize` — синонимы (`_SYNONYMS`: кино→кинотеатр, машина→автомобиль), разбор слитных слов (фудкорт, медиакуб) по словарю базы, опечатки только в словах той же длины (иначе «метро» → «метр»). Экзамен `questions_live.csv` (26): Pro 100% решений, 0 опасных; со старым поиском было 88%.
- Перечни (живой тест 17.10: бот выдавал 8 найденных строк за полный список): `KnowledgeBase.retrieve` вместо голого `search`. На вопрос «что есть» (`_LIST_RE`) с форматом — все строки этого формата (до `LIST_LIMIT`=20), площадки чередуются (`spread_by_venue`, группа = площадка каталога), чтобы в «примеры» попали разные ТЦ. Назван ТЦ без формата — строка «Все форматы» этой площадки; «хочу рекламу» без ТЦ и формата (`_INTENT_RE`) — каталог всех площадок. Каталог строится из прайса сам (`build_catalog`, `catalog_entry`, экраны Инцентра — одна площадка со списком ТЦ). Псевдонимы ТЦ: «аутлет» → BrandStoriesOutlet, «Академ» → «Академический» (`_VENUE_ALIASES`, падежи перечислены — Snowball режет их по-разному).
- Ответ модели: JSON с лишним `\"` разбирается по полям (`_loose_fields`); пропущенный `confidence` = 1.0; ответ простым текстом — один повтор с `FORMAT_REMINDER`; прошлые ответы в истории подаются тем же JSON (иначе модель переходила на простой текст); латиница внутри русских слов («ВЕER») чинится `fix_mixed_script`. Строка прайса для модели (`PriceRow.render`/`parts`) разложена по смыслу: цена «(с НДС 5%, уже в цене)», «Сезонная цена», «Минимальный срок», «Не входит в цену, доплата», «Подробности»; у экранов без доплат — «Печати и монтажа нет: ролик готовит рекламодатель». В одной куче «Условия и доплаты» модель называла НДС доплатой и приписывала печать экранам.
- `unsupported_inclusions` (price_guard): «печать/монтаж/дизайн/производство включены», а в базе так не написано → менеджеру с причиной `terms_mismatch`. Фразы про доплату («дополнительные расходы включают…») не считаются.
- Большой прогон 17.10 (`questions_stress.csv`) и что из него выросло: подбор по бюджету (`parse_budget` → все месячные позиции не дороже, у Бутово срок пустой — тоже месячные), «самая дешёвая» — весь прайс площадки по возрастанию (`_CHEAPEST_RE`, только месячные), перечни и по месту внутри ТЦ (`place_tokens`: «что есть на парковке»), FAQ с сильным совпадением отключает перечни и каталог (`faq_answers`), «мы не арендаторы» → «внешние рекламодатели» (`_NOT_TENANT_RE`, иначе «не» выпадало как стоп-слово).
- Арифметика модели: итог вырезается (`drop_numbers`), только если это цена × срок из вопроса (`months_named`) или цена + другая доплата (`computed_totals`); ×2 «потому что декабрь» — выдумка, к менеджеру. «Умножьте сумму на три» вырезается. Хвост «свяжитесь с менеджером» убирается, если модель не ставила needs_manager и без него остаётся ответ; обещание («менеджер пришлёт/уточнит/подтвердит», `_MANAGER_PROMISE_RE`) — всегда к менеджеру.
- JSON GigaChat ломает по-разному: `\"` внутри, пустые имена полей (`"": 1`), хвост без имён (`…размерам.: false}`), обрыв без `}` — всё разбирается `_loose_fields`/`_LOOSE_TAIL_RE`; неразборчивое — к менеджеру, сырой JSON клиенту не уходит. «Needs Manager: false.» в тексте вырезается; «контекст», please/sorry — к менеджеру (фраза «согласно предоставленным данным» с 19.10 вырезается). Подпись «Условия и доплаты:» из ответа убирается.
- Стоп-темы добавлены по прогону: просьбы прислать (пришл, скинь, фото, КП, коммерческ), охват, форма собственности (ИП, ООО, юрлицо, самозанятый — модель выдумывала «работаем с ИП»).

  Перед публикацией `app/core/versions.py` — быстрый экзамен без модели (~0,5 с): контрольные вопросы из `EXAM_FILES`
  (по умолчанию `eval/questions*.csv`, пусто — без них) и проверенная разметка из журнала должны находить `must_contain`
  в выдаче поиска; каждый раздел FAQ/заметок — находиться по своему заголовку. Регрессия (находилось — перестало, кроме
  ожидаемого после смены цены) или новое противоречие (две цены на одно место; сумма в заметке не из прайса; почти тот
  же вопрос с другими числами в ответе) блокируют публикацию, кнопка «Опубликовать всё равно». Откат — «Вернуть» в
  истории: снимок возвращается и в черновик (неопубликованное — в `kb_versions/черновик-до-отката-*`, `.obsidian` не
  трогаем). `dialogs.kb_version` — по какой версии ответил бот. Повторное утверждение того же вопроса —
  прежний кандидат `superseded`. На текущей базе: 570 из 579 проверок проходят, противоречий 0.
- Опора ответа (21.10): `KnowledgeBase.ungrounded_focus` — на вопрос «да/нет» («есть ли звук?») модель отвечает
  утвердительно словом, которого нет в найденном контексте (с синонимами, сокращениями «сек», общим корнем) →
  `ungrounded`, к менеджеру. Отказ («нет, у нас только…») и вопросы «какой/что/где» не трогаем. Нашлось демо холодного
  старта: при базе из одного прайса Pro ответил «звук присутствует». На ~1480 сохранённых ответах шести моделей —
  0 ложных срабатываний, 3 пойманных опасных. Противоречие («без звука» в базе, «звук есть» в ответе) так не поймать.
  `_GUESS_RE` ещё ловит «часто используется …» и «не указано, однако …» (догадка про формат файла для ДЕПО).
  Пробовали и откатили (21.10) подтягивать в контекст строку прайса по сумме из найденной заметки: убрало 2 лишние
  передачи по пакетам ВЕЕР («на всех экранах» не находит «на всех медиа-носителях»), но вернуло суммы из заметок
  в обход решения 20.10 — одна цена встречается у разных позиций (80 000 ₽: промо-зона и партнёрство), и Pro назвал
  цену промо-зоны «арендой атриума под фестиваль». Пакеты ВЕЕР пока уходят менеджеру через проверку цен.
- Демо холодного старта: `python -m tools.demo_cold_start [--offline] [--keep DIR] [--admin PORT]` — в базе только
  прайс экранов ВЕЕР → вопросы уходят менеджеру → кандидаты из его ответов → утверждение и публикация → бот отвечает на
  новые формулировки → документ с другими цифрами упирается в противоречие. `--admin 8010` поднимает только админку демо.

## Принятые решения (не менять без обсуждения)

- **Только российские модели (GigaChat, YandexGPT) и данные в РФ.** Anthropic и OpenAI не обслуживают Россию, обход через зарубежный сервер нарушает их условия; по 152-ФЗ ПДн россиян нельзя хранить в зарубежных БД (штраф юрлицу 1–6 млн ₽). Не добавлять Claude/OpenAI как провайдер по умолчанию.
- **Цены только из `prices.csv`, модель их не считает.** Цена, названная конкретному клиенту в личном чате, может быть признана офертой (ст. 435 ГК; публичная оферта ст. 437 — не наш случай).
- **ПДн минимизированы:** в журнале только `chat_id` и текст, без имён и телефонов.
- **Режим черновиков — главное отличие от конкурентов** (Salebot, BotHelp, Chat Data отвечают сами, без подтверждения человеком).
- **Telegram — канал пилота, MAX — второй канал.** В MAX бот работает только от организации (ИП/юрлицо/самозанятый после верификации), ответов с личного аккаунта там нет. Telegram в РФ замедляют с февраля 2026, поэтому каналы — через адаптеры.
- Ограничение Telegram: бот отвечает только в чатах, где клиент писал за последние 24 часа. С Bot API 10.0 (май 2026) Premium для бизнес-ботов не нужен, а бот подключается через Настройки → Автоматизация чатов (старый путь «Telegram для бизнеса → Чат-боты» устарел; тексты в `telegram_business.py` и README пока со старым путём).

## Известные ограничения

- Проверка «сумма ↔ ТЦ» смотрит на ТЦ, но не на формат и срок внутри одного ТЦ (цена будней вместо выходных) — это ловят экзамены и судьи.
- Перечни целиком отданы модели: она часто называет 3–5 строк из 13; бот честно дописывает «это часть вариантов», но сам список кодом не строит.
- Модель иногда дописывает «подробнее сообщит менеджер» к полному ответу — это обещание, ответ уходит менеджеру (безопасно, но лишняя эскалация).
- Стоп-темы — по началу слова; вторую часть через дефис («промо-акция») не ловят намеренно.

## Стиль

- Код и комментарии — на русском там, где это тексты для пользователя и докстринги; идентификаторы на английском.

- Зависимости устанавливать из `requirements.lock` (приложение) или `requirements-dev.lock` (разработка), с проверкой хешей. После правок запускать `make check`.
- Для документации aiogram, FastAPI и HTTPX использовать Context7, когда он доступен; для GigaChat — документацию Сбера.
