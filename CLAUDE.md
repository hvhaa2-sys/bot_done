# ИИ-помощник менеджера по продажам

Учебный проект (УрФУ, ИРИТ-РтФ, ИВТ, 2 курс, проектный практикум, команда 5 человек).
Сервис отвечает на типовые вопросы клиентов в мессенджере от имени менеджера по базе знаний компании.
Пилотный клиент — менеджер, продающая рекламу в торговом центре в Екатеринбурге; клиенты пишут ей в Telegram,
второй канал — бот компании в MAX.
Защита перед комиссией, где в основном бизнесмены: нужны живое демо, метрики пилота и экономика.

**В проекте работают два агента (Claude Code и Codex). Перед правками прочитай `docs/КООРДИНАЦИЯ.md`: кто что делает и какие файлы заняты.**

Здесь только то, что нужно в каждой сессии. История правок с датами, почему появилась каждая проверка и цифры
прогонов — в `docs/ЖУРНАЛ.md` (искать по имени функции или константы). Новые записи такого рода дописывай в конец
журнала, а сюда — только новое правило или подвох, о котором должен знать каждый следующий заход.

## Команды

Системный `python3` на машине — 3.9, поэтому окружение в `.venv` (brew python3.13): все команды через `.venv/bin/python`.

```bash

make install-dev                    # Ruff, pytest-cov, pip-audit и импорт документов
make check                          # линтер + тесты с покрытием строк/веток (1200+ тестов, без сети)

python -m app.check                  # перед живым тестом: ключ GigaChat, токен, Business Mode, вебхук

python -m eval.ci_gate               # экзамены как в CI: не хуже eval/ci_baseline.json
python -m eval.run_eval --provider mock
python -m eval.run_eval --compare mock,gigachat

python -m eval.run_eval --questions eval/questions_personas.csv  # 169 вопросов от субагентов-персон: малый бизнес, медиабайеры, «живые» сообщения, red-team
python -m eval.run_eval --questions eval/questions_kb.csv       # 115 вопросов по документам с Яндекс.Диска (заметки: трафик, требования, правила ТЦ)

python -m eval.run_eval --questions ... --repeat 2   # плавающие решения; must_contain: число целиком, «a|b», «!x» — запрет; fact_errors — сумма не из прайса или чужого ТЦ
python -m tools.max_sandbox --offline [--admin PORT]  # поддельный MAX Bot API + настоящий бот, страница с чатами клиентов и менеджера
python -m tools.demo_cold_start [--offline]           # демо холодного старта: пустая база растёт из ответов менеджера
```

## Архитектура

Конвейер ответа (`app/core/assistant.py`):
1. Стоп-темы (`data/kb/stop_topics.txt`: скидки, договор, оплата…) → сразу менеджеру, модель не вызывается.
   Без модели отвечают и шаблоны: каталог площадок (`CATALOG_MESSAGE`), не наш ассортимент (`OFF_RANGE_MESSAGE`,
   `BILLBOARD_MESSAGE`); вопросы о занятости (`_AVAILABILITY_RE`) — менеджеру.
2. Поиск BM25 по прайсу, FAQ и заметкам (`KnowledgeBase.retrieve` в `app/core/knowledge.py`, стемминг Snowball
   с поправками `_STEM_FIX` в `text.py`). Ниже `RETRIEVAL_MIN_SCORE` → менеджеру.
3. Модель отвечает строго по найденным фрагментам и возвращает JSON `{answer, confidence, needs_manager}`.
   GigaChat ломает JSON по-разному — разбирает `_loose_fields`, неразборчивое уходит менеджеру, сырой JSON клиенту не уходит.
4. Проверки ответа (`price_guard.py`, `answer_grounding.py`, проверки в `assistant.py` и `knowledge.py`): сумма не из
   прайса, сумма чужого ТЦ, формата или периода, «включено» без основания в базе, обещания и догадки, латиница не из
   контекста. По части причин модель один раз переписывает ответ с подсказкой (`retry_hint`), иначе — менеджеру.
   Код сам дописывает условия строки, сезонную цену (`add_season_prices`) и недостающие строки перечня (`complete_partial_list`).
5. `needs_manager` или уверенность ниже `CONFIDENCE_THRESHOLD` → менеджеру. `confidence` от GigaChat почти всегда 1.0,
   поэтому эскалацию на деле даёт `needs_manager`.

Модули:
- `app/llm/` — модели за интерфейсом `LLMProvider`: `gigachat` (REST, OAuth), `openai` (любой OpenAI-совместимый API,
  в т.ч. YandexGPT), `mock` (без сети, отдаёт первый фрагмент контекста).
- `app/channels/flow.py` — логика режимов, не зависит от мессенджера; каналы — адаптеры рядом, ядро не трогаем:
  `telegram_business.py` (aiogram 3, Telegram Business, хендлеры в фабрике `make_router()`), `max_api.py` + `max_bot.py`
  (бот организации в MAX: вебхук или долгий опрос, пересылка менеджеру всего, на что бот не ответил, кнопки, заявка
  с контактом), `observation.py` (наблюдение), `voice.py` (голосовые — расшифровка и черновик только менеджеру).
  Клиент пишет кусками — `MessageBuffer` ждёт тишины и отвечает на всё разом.
- `app/core/conversation.py` — память разговора: ТЦ, город, формат, место, срок, бюджет и тип клиента берутся только
  из слов клиента. `client_intent.py`, `real_flow.py` — отменённые просьбы и ответы действующим клиентам.
- `app/core/candidates.py`, `candidate_review.py`, `learning.py` — база из переписки и раздел «Обучение»: кандидат
  живёт в таблице `candidates` и до утверждения в поиск не попадает.
- `app/core/versions.py` — версии базы: `data/kb` — черновик, бот отвечает по снимку `data/kb_versions/<номер>`;
  перед публикацией — быстрый экзамен без модели, регрессия или противоречие блокируют публикацию.
- `app/admin.py` — FastAPI-админка без шаблонизатора: HTML в f-строках, всё через `html.escape`, работает и без
  JavaScript. Цвета — токены в начале `CSS`, шрифты локальные (`app/static/fonts`), к Google не обращается.
- `app/services.py` — настройки из админки хранятся в SQLite (таблица `settings`) поверх `.env` и применяются без
  перезапуска. Ключи и токены — только в `.env`.
- `app/db.py` — SQLite: подключения, диалоги и их статусы, паузы, кандидаты, наблюдение, расход модели (`usage`).
- `app/core/pii.py` — маскировка телефонов, почт и карт в импорте и журнале.
- `eval/` — стенд качества (`run_eval`, `ci_gate`, наборы `questions*.csv`, симуляции). `tools/` — импорт переписки
  и документов, песочница MAX, демо, пакет переноса на сервер.

Режимы подключения: `draft` — карточка менеджеру с кнопками «Отправить/Пропустить», ответ на карточку своим текстом —
правка; `auto` — бот отвечает сам, при эскалации клиенту «Уточню и вернусь»; `observe` (синоним `watch`) — бот
молчит и только собирает переписку и время ответа менеджера; `off` — молчит и ничего не сохраняет. Если менеджер
пишет в чат сам, бот молчит `MANAGER_PAUSE_MINUTES`.

База знаний `data/kb/`: `prices.csv`, `faq.md`, `stop_topics.txt`, `notes/**/*.md` (папка Obsidian, файл на тему,
в начале YAML `тц: …`, каждый раздел «## Вопрос» — отдельный фрагмент поиска). Утверждённое из переписки —
`notes/Из переписки/<ТЦ>.md` или `Общее.md`. Пример с выдуманными ценами для тестов — `tests/fixtures/`.

## Осторожно

- **Пустая переменная не выключает Telegram.** `_load_dotenv` не даёт пустой переменной перекрыть `.env`, поэтому
  `TELEGRAM_BOT_TOKEN= python -m app` опрашивает настоящего бота, забирает его события (в них переписка клиентов)
  и конфликтует с живым. Запускать без Telegram только с подменой `app.config._load_dotenv` и чистым окружением
  либо через `replace(settings, telegram_bot_token="")`, как в `tools/max_sandbox.py`.
- **Живой бот работает на Mac пользователя** (LaunchAgent `local.ai-sales-assistant`, лог
  `~/Library/Logs/ai-sales-assistant.log`) и занимает порт 8000: `preview_start admin` в него упрётся. Админку открывать
  в браузере, для проверок — `max-sandbox` из `.claude/launch.json`, перезапуск после правок — `deploy/mac-autostart.sh`.
- **GigaChat на freemium — один запрос за раз.** Два экзамена параллельно или экзамен рядом с живым ботом дают 429:
  экзамены гонять по очереди.
- **Каждая правка промпта — экзаменами на Pro** (минимум основной и live): безобидная на вид формулировка уже давала
  лишние передачи менеджеру, её откатывали.
- **Проверки ответа опираются только на текущий контекст базы.** Ни слова клиента («менеджер сказал, печать входит?»),
  ни прошлые ответы бота цену, число или условие не подтверждают.
- **VPN Happ на Mac пользователя:** MAX и GigaChat ходят напрямую, в обход VPN (`docs/DIRECT-CONNECTION.md`).
  Настройки VPN не трогаем — это делает пользователь. Сайт dev.max.ru через VPN не открывается; API MAX сверять
  по официальной схеме github.com/max-messenger/api-schema (`schema.yaml`).
- **Docker:** всё изменяемое состояние — в `data/` (один постоянный том). Новые файлы в `app/static/` попадают
  в образ только благодаря `!app/static/**` в `.dockerignore`.
- **Токен админки — только в cookie:** `?token=` в ссылке входит один раз и уходит на адрес без токена, в журналах
  токен маскируется. Не печатать его в лог и не класть в адреса.

## Принятые решения (не менять без обсуждения)

- **Только российские модели (GigaChat, YandexGPT) и данные в РФ.** Anthropic и OpenAI не обслуживают Россию, обход через зарубежный сервер нарушает их условия; по 152-ФЗ ПДн россиян нельзя хранить в зарубежных БД (штраф юрлицу 1–6 млн ₽). Не добавлять Claude/OpenAI как провайдер по умолчанию.
- **Цены только из `prices.csv`, модель их не считает.** Цена, названная конкретному клиенту в личном чате, может быть признана офертой (ст. 435 ГК; публичная оферта ст. 437 — не наш случай).
- **ПДн минимизированы:** в журнале только `chat_id` и текст, без имён и телефонов.
- **Режим черновиков — главное отличие от конкурентов** (Salebot, BotHelp, Chat Data отвечают сами, без подтверждения человеком).
- **Telegram — канал пилота, MAX — второй канал.** В MAX бот работает только от организации (ИП/юрлицо/самозанятый после верификации), ответов с личного аккаунта там нет. Telegram в РФ замедляют с февраля 2026, поэтому каналы — через адаптеры.
- Ограничение Telegram: бот отвечает только в чатах, где клиент писал за последние 24 часа. С Bot API 10.0 (май 2026) Premium для бизнес-ботов не нужен, а бот подключается через Настройки → Автоматизация чатов (старый путь «Telegram для бизнеса → Чат-боты» устарел; тексты в `telegram_business.py`, админке и README уже с новым путём).

## Известные ограничения

- Проверка «сумма ↔ формат» осторожная: сумма, которая есть и у нужного формата, и общие слова места (баннер и
  лайтбокс у одной входной группы) ошибкой не считаются. Цену будней вместо выходных ловит только для строк с днями в сроке.
- Перечень дописывается кодом только для вопроса с форматом и не длиннее 8 строк; на вопрос без формата («что есть
  в ВЕЕР?») — по-прежнему только «это часть вариантов».
- «Подробнее расскажет менеджер» убирается только целой фразой из `_GENERIC_TAIL_RE`; другие обороты с обещанием
  менеджера (безопасно) уходят ему.
- Стоп-темы — по началу слова; вторую часть через дефис («промо-акция») не ловят намеренно.

## Стиль

- Код и комментарии — на русском там, где это тексты для пользователя и докстринги; идентификаторы на английском.
- Новая логика — с тестом в `tests/` (без сети: `FakeLLM`, подмена `bot.send_message`).
- Python 3.11+, без тяжёлых зависимостей в ядре.
- Зависимости устанавливать из `requirements.lock` (приложение) или `requirements-dev.lock` (разработка), с проверкой хешей. После правок запускать `make check`.
- Для документации aiogram, FastAPI и HTTPX использовать Context7, когда он доступен; для GigaChat — документацию Сбера.
